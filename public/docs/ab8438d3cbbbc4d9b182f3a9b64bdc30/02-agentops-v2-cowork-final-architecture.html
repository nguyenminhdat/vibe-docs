Diagram 4 · Standalone vs Managed · Standalone = Phase 2, cần ADR

Một binary Cowork, một core thực thi — chế độ chỉ đổi nơi đặt Não, nguồn chính sách, LLM và audit

Thông điệp: 7 khối ở giữa là cùng một code cho cả hai chế độ. Standalone = máy tự đủ (cá nhân, việc ngắn). Managed = máy là tay của AgentOps; liên kết máy bằng PKCE là chuyển chế độ, không cài lại.

100%
Cần ADR trước khi build Standalone (AD-11): plan Cowork v3 chưa có chế độ này và đang chốt D-18 (mọi văn bản vào/ra qua guard server) + D-24 (không giữ state bền trên máy). Standalone lệch cả hai → đề xuất: policy pack ký sẵn + guard model cục bộ (Gemma 4 E4B qua Ollama) + journal cục bộ; hành động external luôn xác nhận từng lần; không có workflow lịch/bền. B quyết.

100%
Intent + plan

Managed: T0/T1 trên server → chiến lược "Phức hợp" (file máy + KB + hành động). Standalone: cùng core, LLM cục bộ.

Thực thi

Managed: đọc file trên máy, phân tích bằng op xác định trên server (không LLM). Standalone: đọc + phân tích trên máy.

Duyệt + MCP

Cả hai: form typed → validate xác định → xem trước → xác nhận → tools/call (ADR-0053). Managed đi Kong bằng danh tính Keycloak; Standalone bằng token MCP cá nhân.

Giá trị demo

một câu lệnh thay chuỗi thao tác tay qua Excel → KB → SSC; 0 ticket ghi khi chưa duyệt; mọi bước có audit; "Lưu thành quy trình" → lần sau chạy theo lịch trên Temporal.

2

Dữ liệu "bẩn" xử lý tổng quát

Bảng sao kê bắt đầu dòng 7, 4.782 ô gộp · số tiền dạng text "1,234" · 2 dòng tổng cuối · 3 dòng Dư đầu/cuối kỳ không có khoá.

Nhận file theo cột, không theo tên

File tên "bravo SP" thực chất là sao kê MB (có cột BÚT TOÁN, PHÁT SINH CÓ). Context grounding dựa vào schema.

Silent-wrong bị chặn

5 khoá BankTransactionId trùng. Nối thẳng không gộp → 34 dòng lệch (10 dòng giả) và tổng không khớp. Guard đã có trong code.

Governance thật

Team có archetype transform/report = L3 (đã kiểm get_delegation_level) → kích hoạt cần A duyệt + RAI checklist. Không ghi ra hệ thống ngoài.

Xem op-chain sinh từ intent (rút gọn, đúng schema operation_kinds.schema.json) 
ct  = fetch     {source: upload}                                                  # Nạp giao dịch CT · form_upload L0
ct  = transform {rules: [drop_rows BankTransactionId rỗng,
                         rename {BankTransactionId: KEY_ID, DebitAmount: AMOUNT}]}
ct  = aggregate {group_by: [KEY_ID], aggregations: [{field: AMOUNT, func: sum, as: AMOUNT},
                 {field: DocDate, func: first, as: NGAY}, {field: Description, func: first, as: NOI_DUNG},
                 {field: DocNoRSA, func: first, as: DocNoRSA}]}                       # 5 khoá trùng → gộp
mb  = fetch     {source: upload, sheet: "Thông tin giao dịch"}                      # header tự dò: dòng 7
mb  = transform {rules: [drop_rows "BÚT TOÁN" rỗng, cast "PHÁT SINH CÓ" → number,
                         rename {"BÚT TOÁN": KEY_ID, "PHÁT SINH CÓ": AMOUNT,
                                 "NGÀY HẠCH TOÁN": NGAY, "NỘI DUNG": NOI_DUNG}]}
mb  = aggregate {group_by: [KEY_ID], aggregations: [{field: AMOUNT, func: sum, as: AMOUNT}, …]}
rec = reconcile {left_ref: ct, right_ref: mb, key: [KEY_ID],
                 compare_fields: [AMOUNT], tolerance: 0}                              # outer · L2 · _left/_right
out = transform {rules: [rename {AMOUNT_left: CT_AMOUNT, AMOUNT_right: SP_AMOUNT}, fill … = 0,
                         derive CHENH_LECH = SP_AMOUNT − CT_AMOUNT, drop_rows CHENH_LECH == 0,
                         derive KET_QUA = CHENH_LECH < 0 ? "HT âm" : "Báo có"]}
rpt = report    {format: xlsx, columns: [KEY, CT_AMOUNT, SP_AMOUNT, CHENH_LECH, KET_QUA,
                 NGAY_CHUNG_TU, NOI_DUNG, DocNoRSA, "Note check tay"]}                  # L3
